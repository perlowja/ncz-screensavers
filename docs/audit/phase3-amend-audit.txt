5.  glColorMaterial no-op correctness — comprehensive proof
----------------------------------------------------------------------

This finding had two parts:
  (a) The shader pair's behavior with/without GL_COLOR_MATERIAL
      being honored.
  (b) crackberg.c's specific call pattern, to confirm (a) applies.

Step 1 — What does crackberg.c actually do around lighting/material?

  $ grep -nE 'glMaterial' src/crackberg.c
  (no matches)

  $ grep -nE 'glColorMaterial' src/crackberg.c
  1225:        glColorMaterial(GL_FRONT_AND_BACK, GL_AMBIENT_AND_DIFFUSE);

  $ grep -nE 'glEnable\(GL_(LIGHTING|LIGHT0|COLOR_MATERIAL)' src/crackberg.c
  1221:        glEnable(GL_LIGHTING);
  1222:        glEnable(GL_LIGHT0);
  1223:        glEnable(GL_COLOR_MATERIAL);

  $ grep -nE 'glColor3d|glColor3f' src/crackberg.c | wc -l
  12

  So crackberg.c enables GL_LIGHTING + GL_LIGHT0 + GL_COLOR_MATERIAL
  and calls glColorMaterial(GL_FRONT_AND_BACK, GL_AMBIENT_AND_DIFFUSE)
  once (line 1225). It never calls any glMaterial* function. Its
  per-vertex colors come from glColor3f/glColor3d (12 calls).

Step 2 — Standard GL1 behavior under
GL_COLOR_MATERIAL=GL_AMBIENT_AND_DIFFUSE with no glMaterial*:

  - material.ambient stays at default GL_AMBIENT (0.2, 0.2, 0.2, 1.0)
  - material.diffuse stays at default GL_DIFFUSE (0.8, 0.8, 0.8, 1.0)
  - material.specular stays at default (0, 0, 0, 1)
  - material.emission stays at default (0, 0, 0, 1)
  - With GL_COLOR_MATERIAL=AMBIENT_AND_DIFFUSE: BEFORE each draw,
    the runtime OVERWRITES material.ambient AND material.diffuse with
    the current color (glColor*).
  - So at draw time: material.ambient = current_color, material.diffuse
    = current_color, material.specular = (0,0,0,1) (no contribution),
    material.emission = (0,0,0,1) (no contribution).
  - Fragment color = ambient_term + diffuse_term + emission_term + specular_term
                   = (mat.amb * scene_amb) + (mat.diff * light_color * ndotl)
                   + 0 + 0
                   = (current_color * scene_ambient)
                   + (current_color * light_color * ndotl)
                   = current_color * (scene_ambient + light_color * ndotl)

Step 3 — gles3 shader pair behavior with has_material=false (the
crackberg.c state, since crackberg never calls glMaterial* → g_im.
has_material stays false):

  Vertex shader (gles3_compat.c line 259):
    vec4 base = u_has_material ? u_material_color : a_color;
  → with has_material=false: base = a_color = per-vertex glColor* input
  → v_color = vec4(base.rgb, base.a) = (cur_color, 1)

  Fragment shader (gles3_compat.c line 294):
    vec3 lit = v_color.rgb * (u_ambient + u_light_color * ndotl);
  → frag.rgb (no texture path) = a_color * (u_ambient + u_light_color * ndotl)

  With u_ambient set to scene_ambient (gles3_compat.c default (0.2,0.2,0.2),
  OR overridable via glLightModelfv(GL_LIGHT_MODEL_AMBIENT, ...) which
  ncz_im_light_ambient writes to g_im.light_ambient — line 791-793) and
  u_light_color set to light_color (gles3_compat.c default (1,1,1), OR
  overridable via glLightfv(GL_LIGHT0, GL_DIFFUSE, ...) → ncz_im_light_
  diffuse writes to g_im.light_color — line 798-800):

    frag.rgb = a_color * (scene_ambient + light_color * ndotl)

Step 4 — Are these two formulations equal?

  Standard GL1 under GL_COLOR_MATERIAL=AMBIENT_AND_DIFFUSE:
    frag.rgb = current_color * scene_ambient
             + current_color * light_color * ndotl
             = current_color * (scene_ambient + light_color * ndotl)

  gles3 shader with has_material=false:
    frag.rgb = a_color * (scene_ambient + light_color * ndotl)

  Same expression. a_color is the per-vertex color fed in by
  glColor3f/glColor3d (each vertex gets the current color as its
  a_color attribute, see ncz_im_color3f and g_im.cur_color plumbing).
  current_color in the GL1 formulation is the same thing — the
  current color at the time of the glVertex* call.

  They are mathematically identical for any a_color, scene_ambient,
  light_color, and ndotl.

Step 5 — What about the other material slots (specular, emission)?

  In standard GL1 with crackberg's state (no glMaterial* ever called,
  GL_COLOR_MATERIAL=AMBIENT_AND_DIFFUSE):
    - material.specular = default (0, 0, 0, 1) → specular term = 0
    - material.emission = default (0, 0, 0, 1) → emission term = 0

  In gles3 shader with has_material=false:
    - The shader only has `u_ambient + u_light_color * ndotl`. No
      specular or emission term.

  Both formulations produce 0 contribution from specular and emission
  for crackberg's specific state. So the two formulations agree on
  specular AND emission as well as on ambient+diffuse.

Step 6 — What if crackberg DID call glMaterial*? Then the no-op
becomes incorrect. The 12 other Phase 3 + glFrustum-cohort hacks
also never call glMaterial* (transcript below), so the no-op is
correct for ALL of them, not just crackberg.

  $ grep -nE 'glMaterial' src/{cityflow,covid19,crackberg,cubenetic,cubestorm,cubetwist,cubicgrid,dangerball,discoball,energystream,highvoltage,stonerview,lament}.c
  (no matches)

  Zero glMaterial* calls across all 13 hacks. So the no-op is
  observationally equivalent to honoring the flag for all 13.

Step 7 — Combined conclusion:

  For crackberg (and the other 12), the gles3 shader pair WITHOUT
  glColorMaterial routing produces the same fragment colors as the
  standard GL1 pipeline WITH glColorMaterial routing, because:
    (i)  crackberg never calls glMaterial*, so g_im.has_material
         stays false, the vertex shader picks a_color.
    (ii) gles3 fragments as `a_color * (u_ambient + u_light_color *
         ndotl)`. Standard GL1 with AMBIENT_AND_DIFFUSE color material
         and zero material spec/emission also fragments as
         `current_color * (scene_ambient + light_color * ndotl)`.
    (iii) a_color and current_color are the same value (per-vertex
          glColor* input).
    (iv) u_ambient is scene_ambient, u_light_color is light_color.

  Therefore the no-op stub is observationally correct for ALL 13
  hacks in this dispatch. A future port that DOES combine glMaterial*
  with glColorMaterial is the trigger condition for the real
  material-routing implementation work (track a `g_im.color_material
  _mode` flag set by glColorMaterial, route inside ncz_im_color()
  to g_im.material when the flag is on, flip g_im.has_material).
  The source comment at gles3_compat.c lines ~1722-1768 captures the
  same proof inline.
