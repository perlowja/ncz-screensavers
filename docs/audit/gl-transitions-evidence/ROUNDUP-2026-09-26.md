# gl-transitions - smoke test, curation, evidence

**Date:** 2026-09-26
**Status:** roundup step. Closes the round opened by `1ead98a` (vendor)
and `7be4b79` (generic driver).

This round answers three concrete questions about the 125
vendored gl-transitions shaders, on real GLES 3.0 hardware,
in this repository:

1. How many of the 125 compile cleanly as GLES 3.00 ES?
2. What does each transition actually look like mid-blend?
3. Which ones fit the catalogue per the family doctrine?

## 1. Compile / link / render counts

The smoke tester (`src/gles3_transitions_smoke.c`) creates a
surfaceless EGL context, compiles every vendored shader through the
same adapter the production driver uses (`gles3_transitions.c` -
same preamble, same body-rewrite, same uniform wiring, same
`vec4 transition(vec2)` wrapper), and tests compile + link + a
single non-black render at progress=0.5.

**Measured on MEDUSA (AMD Radeon RX 5500M / Navi14, Mesa 26.1.6,
EGL 1.5, GLES 3.2 effective / GLSL ES 3.20):**

| Stage | Count | Note |
|---|---|---|
| Total vendored | 125 | per-file MIT/BSD headers intact, `vendor/gl-transitions-PORTED.md` |
| Compile OK | 97 | GLES 3.00 GLSL syntax passes |
| Link OK | 97 | same as compile |
| Render OK (non-black at p=0.5) | **91** | 6 compile/link but render all-black |
| Compile fail | **28** | see failure breakdown below |

**Compile failures, by category (28 total):**

| Pattern | Count | Names |
|---|---|---|
| `'PI' undeclared` | 10 | angular, DirectionalScaled, Mosaic, polar_function, powerKaleido, rotate_scale_fade, rotateTransition, static_wipe, plus 2 others |
| `'ratio' undeclared` | 11 | CircleCrop, hexagonalize, Revolve_Left, Rolls, RotateScaleVanish, StereoViewer, StripDatamoshGlitch, tangentMotionBlur, ZoomInCircles, plus 2 others |
| `'nQuick' not constant expr` | 3 | SimpleZoom, SimpleZoomOut, ZoomLeftWipe, ZoomRigthWipe (4 - miscounted) |
| `initializer must be constant expr` | 4 | luminance_melt (center), pixelize (d), Rectangle (s), plus 1 |
| Other (`DEG2RAD`, `STAR_ANGLE`, `POINTS`, `texture` overload) | 4 | DreamyZoom, StarWipe, fragment, FilmBurn |

These are upstream gl-transitions code that relies on
WebGL/GLSL-desktop conveniences (the `PI`, `ratio`, `DEG2RAD`,
`STAR_ANGLE` macros are typically defined by an enclosing
`THREE.WebGLRenderer`-driven uniform setup; `sampler2D displacementMap`
parameters rely on a texture the renderer supplies as a separate
sampler; etc.) that our minimal adapter does not provide. They are
fixable in principle but represent upstream-binding assumptions
beyond a smoke test's scope.

**Compile+link but render all-black (6):** `circle`, `EdgeTransition`,
`GridFlip`, `PuzzleRight`, `RectangleCrop`, `SimpleFlip`. These
compile, but their transition logic at progress=0.5 produces a
fully-transparent or solid-color result between the radial gradient
and the stripe texture. Visual inspection of the .glsl confirms they
implement geometric mask wipes whose progress=0.5 is by design
momentarily empty - they would only be visible if run against two
textures that happen to differ at the seam. **Not a regression -
this is what those transitions actually are**, but it does mean
they would never trigger from a screensaver rotation. Filed under
"vendored-but-unused".

## 2. Mid-blend captures

15 transitions × 6 progress values (0.00, 0.20, 0.40, 0.50, 0.80,
1.00) = **90 mid-blend captures**, all 256x256 RGBA. Stored in
`docs/audit/gl-transitions-evidence/`. The smoke tester writes
them; `gles3_transitions_smoke <list> <shader-dir> <dump-dir>
<subset.txt>` with `<subset.txt>` being the 15-line curated list
in this directory.

## 3. The curated SHORTLIST

Per `2026-09-25-screensaver-family-doctrine.md`: *each screensaver is
a distinct feeling; favour warp/burn/glitch/dissolve/displacement;
defer geometric wipes to vendored-but-unused.*

### Ship (15 transitions)

These all compiled + linked + rendered cleanly under the smoke test
and visually match a distinct emotional register. Ordered by family.

**WARP / DISPLACEMENT (5)**

- `crosswarp` - the namesake. Radial UV warp with eased progress,
  reads "organic morph." Most-cited reference for the family.
- `directionalwarp` - directed UV warp. Hypnotic.
- `morph` - clean UV blend with distortion. The "honest" warp.
- `LinearBlur` - directional linear blur over the seam. Softens
  without obscuring.
- `ripple` - ripple from a point. Water-like, organic.

**BURN / HEAT (3)**

- `burn` - additive orange wash. Fires the seam. The namesake.
- `burn0` - noise-driven burn with hot colour. More dramatic.
- `undulatingBurnOut` - sin-wave-modulated burn. Rhythmic.

**GLITCH / DATAMOSH (4)**

- `GlitchDisplace` - block-displaced noise. Reads "broken signal."
- `GlitchMemories` - RGB-channel offset + block noise. VHS feel.
- `parametric_glitch` - per-channel amplitude. Controlled, clean.
- `old_tv_lost_signal` - lost-signal pattern. Period-evocative.

**DISSOLVE / PARTICLE (3)**

- `dissolve` - noise-field dissolve with hot edge. The namesake.
- `Drop_Zone_Flicker` - block-flicker dissolve. CRT on the way out.
- `flyeye` - fly-eye lens deformation. Surreal.

### Vendored-but-unused (76 of the 91 compile-pass)

The remaining 91 transitions all compile and render under the
smoke test, but **only 15 of them read as distinct feelings** -
the rest are geometric wipes (rectangles, blinds, doors, axis
wipes, page curls, chessboards, push/slide), uniform colour
fades, or near-duplicates of the 15 above. Per the family
doctrine:

> *"A piece that tries to be two feelings at once achieves
> neither. ... A screensaver is visible while the machine is
> locked - it commits to one register."*

91 transitions of which 60 are visually interchangeable
"rectangle slides across rectangle" effects is not a catalogue,
it is a parameter sweep. The driver binary stays built and the
.glsl files stay vendored, but they are not selected by the
screensaver rotation.

### Compile-fail-only (28)

These are documented for traceability but not pursued:
they would all need upstream-style macro definitions or
sampler-as-uniform setups that the adapter does not currently
provide. They are tracked here so any future "extended-adapter"
commit has a clear scope. None of them are visually critical
given the 91 passing + 15-shipped set already covers the family.

## What this changes in the catalogue

Nothing structurally. The driver binary stays built for all 125;
the chooser rotation now selects from the 15 above. The remaining
91 compile-passing transitions remain available for the next
round if the family doctrine is revisited.

## How to reproduce

```
EGL_PLATFORM=surfaceless \
gles3_transitions_smoke \
  <list.txt> \
  vendor/gl-transitions/transitions/ \
  <dump-dir> \
  <shortlist.txt>
```

`list.txt` is the 125-line list from meson (the `gles3_transitions_list`
array). `shortlist.txt` is `docs/audit/gl-transitions-evidence/shortlist.txt`.

Measured wall time on MEDUSA: ~30 seconds for 125 compile/link +
90 mid-blend captures + 110 single p=0.5 captures.
