This commit adds the `ncz_mat4_frustum` matrix builder + `glFrustum`
shim in `gles3_compat.c` (and the matching declaration in
`gles3_compat.h`), then wires those 4 consumers into
`legacy_gles3_hacks` so the helper is not foundation-without-in-
round-consumer. The companion audit for the 2nd commit (the 9
alphabetical ports + crackberg foundations) is in
`phase3-fix-audit.txt`.

4.  Why this is a 1st-class foundation commit, not 2nd-class groundwork
----------------------------------------------------------------------

  [medium] glFrustum-scope finding from the rejected fd3f875
  review: "ships a foundation extension with no in-round consumer"
  → addressed by wiring all 4 known consumers in the SAME round.
  This means a future regression in ncz_mat4_frustum will surface
  in 4 known named binaries (energystream, highvoltage, stonerview,
  lament), not just one future unknown. Bisection stays clean.

  Visual rendering evidence not obtained on this build host (same
  constraint as the rest of the Phase 2 / Phase 3 audits: no
  working Wayland compositor). The ported-only-if-LINKS bar is met
  via the link/ldd/nm evidence above.
