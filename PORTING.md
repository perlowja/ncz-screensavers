# PORTING.md — Mechanical Porting Pipeline for xscreensaver GL Hacks

Round 7 deliverable. This is the recipe that takes an upstream
xscreensaver GL hack (a single .c file in `hacks/glx/`) and ports it
through our native Wayland/EGL/GLES pipeline by:

  1. Linking against **GL4ES** (a libGL.so.1 fixed-function-translation
     shim) so classic GL1 calls work on the GLES2/3-only Mali-G720 GPU.
  2. Linking against a tiny **xscreensaver_compat** shim that satisfies
     the `screenhack.h`/`xlockmore.h` API by routing into our existing
     wl-screenhack EGL/Wayland foundation.

The result: a hack compiles against our binary with **only its `#include`
lines edited** (typically 1-2 lines), the rest of the source is unmodified.

---

## §1 — Architecture

```
                         vendored xscreensaver hack
                         (e.g. src/glmatrix.c)
                                  │
                                  │ calls glBegin, glVertex3f,
                                  │ glRotatef, gluPerspective,
                                  │ glXMakeCurrent, XGetPixel,
                                  │ init_GL, image_data_to_ximage …
                                  ▼
                ┌─────────────────────────────────────┐
                │  xscreensaver_compat.{h,c}          │  ← our shim (this repo)
                │   - glX* passthroughs → EGL         │
                │   - init_GL / xlockmore_mi_init     │
                │   - XGetPixel/XPutPixel over RGBA   │
                │   - image_data_to_ximage (libpng)   │
                │   - XSCREENSAVER_MODULE_2 macro     │
                └──────────────────┬──────────────────┘
                                   │
                                   │ linked into same binary as
                                   │ glmatrix_harness.c (or your own)
                                   ▼
                ┌─────────────────────────────────────┐
                │  glmatrix_harness.c (or wl-screenhack)  │
                │   - Owns Wayland display + EGL ctx  │
                │   - Calls init_cb, draw_cb, etc.    │
                │   - Sets shim globals so glX* calls │
                │     reach our EGL surface           │
                └──────────────────┬──────────────────┘
                                   │
                                   │ app's gl* calls → GL4ES at link time
                                   ▼
                ┌─────────────────────────────────────┐
                │  libGL.so.1 (GL4ES)                 │  ← apt install or
                │   - Translates glBegin/glMatrixMode │     build from source
                │     to GLES2 vertex calls + shader- │
                │     based FFP emulation             │
                └──────────────────┬──────────────────┘
                                   │ uses our EGL context
                                   ▼
                ┌─────────────────────────────────────┐
                │  libGLESv2.so (Mesa panfrost)       │  ← already installed
                │   - Mali-G720 GLES 3.2 driver       │
                └─────────────────────────────────────┘
```

The whole pipeline is **mechanical**: a fresh port is "fetch source →
edit #include lines → add to meson → build". No hand-rewriting of GL
calls.

## §3 — GL4ES build & install (Debian forky arm64)

GL4ES has **no stable release** — it's distributed as a git tree at
https://github.com/ptitSeb/gl4es (HEAD is `v1.1.7-dev`, last commit on
master around 2026-07). For reproducible builds, pin to a specific commit
in your build script.

### 3a. Install on the coordinator's Debian forky arm64 host

The Debian packagers maintain `libgl4es0` (runtime) + `libgl4es-dev`
(headers, but only `gl4eshint.h`/`gl4esinit.h` — **not** a full
`GL/gl.h`). For our use, this is sufficient because we vendor
`include/GL/gl.h` from upstream gl4es into our own source tree
(`src/gl4es_include/GL/gl.h`). The runtime is supplied by the
Debian package; the build is self-contained.

```bash
sudo apt install -y libgl4es0 libgl4es-dev libpng-dev
ls /usr/lib/aarch64-linux-gnu/gl4es/libGL.so.1     # confirm runtime present
ls /usr/include/gl4es/                              # gl4eshint.h, gl4esinit.h
```

The actual library path on Debian forky is
`/usr/lib/aarch64-linux-gnu/gl4es/libGL.so.1` (not
`/usr/lib/gl4es/libGL.so.1` — that's the upstream install layout).
The meson build auto-detects this.

If the libgl4es packages aren't available (e.g. you need a newer
gl4es master than Debian's 1.1.6+ds-3), build from source:

```bash
git clone https://github.com/ptitSeb/gl4es.git /tmp/gl4es-build
cd /tmp/gl4es-build
git checkout <pin-commit>     # pin for reproducibility
mkdir build && cd build
cmake .. \
  -DNOEGL=1 \
  -DNOX11=1 \
  -DDEFAULT_ES=2 \
  -DUSE_CLOCK=ON \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DCMAKE_C_FLAGS="-mcpu=cortex-a715 -mtune=cortex-a715 -O2"
make -j$(nproc)

sudo mkdir -p /usr/lib/gl4es
sudo cp -v libGL.so.1* /usr/lib/gl4es/
sudo chmod 0755 /usr/lib/gl4es/libGL.so.1
```

Then point the build at the manual install:

```bash
meson setup build -Dgl4es-lib-dir=/usr/lib/gl4es/libGL.so.1
```

### 3b. Flag notes (what each does and why we picked it)

| Flag | What it does | Why this value |
|---|---|---|
| `-DNOEGL=1`      | Skip GL4ES's own EGL display/context — we provide ours | Required: we own the EGL context. |
| `-DNOX11=1`      | Drop all glX* code paths; ~5K LOC of dead GLX emulation | No X11 on this system. |
| `-DDEFAULT_ES=2` | GL4ES targets GLES2 GLSL shaders (we want it to run on a GLES3.2 driver) | Mali-G720 driver is GLES3.2; ES2 shaders work as a subset. |
| `-DUSE_CLOCK=ON` | Pull in `-lrt` for clock_gettime (used for FPS profiling) | Benign on glibc. |

### 3c. Runtime environment (REQUIRED for both gl4es_triangle and glmatrix_demo)

```bash
export LIBGL_NOTEST=1     # CRITICAL — skip GL4ES's broken PBuffer probe (issue #436)
export LIBGL_ES=2         # match DEFAULT_ES=2 (default but explicit)
export LIBGL_NOBANNER=1   # quieter logs
```

`LIBGL_NOTEST=1` is **mandatory**. Without it, GL4ES's `initialize_gl4es`
constructor calls `eglGetDisplay(EGL_DEFAULT_DISPLAY)` to create a
throwaway probe PBuffer + context, which on Mesa/panfrost returns
`EGL_BAD_DISPLAY` if our app already bound the display (it has). With
the env var, GL4ES skips the probe and uses sensible defaults — see
`src/gl/hardext.c` lines 36-83.

### 3d. GL4ES EGL/GLES contracts (what we promise)

1. **Our EGL context is GLES2** (`EGL_CONTEXT_CLIENT_VERSION=2`), not
   3. GL4ES generates GLSL 100/120 shaders; if we set CLIENT_VERSION=3
   it can still work but unnecessary — and some old GL4ES versions
   mis-detect.
2. **`eglMakeCurrent` is called by US, by the harness, BEFORE any
   `gl*` call.** GL4ES does NOT call `eglMakeCurrent` itself under
   `NOEGL=1`; it uses `eglGetCurrentContext()` to discover the active
   context.
3. **The binary's rpath includes `/usr/lib/gl4es`** so libGL.so.1
   resolves to GL4ES's version, not Mesa's. The meson build does this
   automatically (see `link_args:` in `meson.build`).

## §4 — Vendoring an xscreensaver hack (general recipe)

### 4a. Fetch the source

The canonical source is `https://www.jwz.org/xscreensaver/xscreensaver-6.15.tar.gz`.
The GitHub mirror at `https://github.com/Zygo/xscreensaver` works too but
many raw.githubusercontent.com URLs 404 because paths changed in 6.x.

```
tar xf xscreensaver-6.15.tar.gz
```

GL hacks live in `hacks/glx/`. Pick ones that are SIMPLE — single file,
minimal dependencies, no display lists or external libraries beyond GLU.
Good first candidates:
- `glmatrix.c` (1,076 lines; uses only glBegin/glVertex/glRotate + 2 GLU calls + a PNG)
- `gears.c`   (953 lines; adds glLight/glMaterial)
- `boing.c`   (664 lines; uses gltrackball)
- `boxed.c`   (1,360 lines; uses gluBuild2DMipmaps)

### 4b. Decide what shim calls the hack uses

`grep -E 'MI_|init_GL|glXMake|glXSwap|do_fps|current_device|XSCREENSAVER|realloc|ModeSpecOpt|XrmOptionDescRec|get_string_resource|get_boolean_resource|XImage|XGetPixel|XPutPixel|XDestroyImage|image_data_to_ximage|TimeOfDay|localtime|strftime' hacks/glx/<hack>.c`

Cross-reference against the symbols exposed by `src/xscreensaver_compat.h`.
If the hack uses anything not in the shim, add it. Common additions:

| Symbol added | Why | Where |
|---|---|---|
| `XAllocColor`, `XFreeColors`, `XParseColor` | Color allocator API (utils/colors.h) — most hacks that need a palette use this | Add to `xscreensaver_compat.h` + `.c` |
| `XSync`, `XFlush`         | Force X request drain — most hacks use one of these near init | Add to shim (XSync is no-op; XFlush is no-op) |
| `mi->cycles`, `MI_CYCLES` | Loop exit counter (`atlantis`, `bsod`, etc.) | Already in shim; just wire a quit-after-N-cycles check in the harness |
| `get_string_resource`, `get_boolean_resource` | X resource lookup; almost always called from `init_GL` not from the hack itself | Already stubbed in shim (returns empty/False) |
| `XFontStruct`, `XLoadQueryFont`, `XFreeFont`, `XTextWidth`, `XDrawString` | Text rendering for non-GL overlay labels | Major addition — defer; for round 7+1+ this would be a separate subagent work item |

For each symbol the hack uses but the shim doesn't yet expose, **add to
the shim, do NOT modify the hack source**. The shim is the single
place to extend.

### 4c. Edit only the `#include` lines (typical diff is 1-3 lines)

```diff
- #include "xlockmore.h"
- #include "ximage-loader.h"
+ #include "xscreensaver_compat.h"
```

If the hack has `#include "images/gen/<name>_png.h"` (PNG asset) or
similar auto-generated headers, leave them — we generate them with
xscreensaver's own `utils/bin2c` script at build time. Add a `custom_target`
in `meson.build` that runs `bin2c` for each PNG asset.

### 4d. Register the hack in the build

Add a new executable in `meson.build` (model on `glmatrix_demo`):

```meson
executable(
    '<hack>_demo',
    files([
        '<hack>_harness.c',           # driver; copy of glmatrix_harness.c
        'xscreensaver_compat.c',      # always
        '<hack>.c',                   # vendored source
        'image_data_to_ximage.c',     # always (PNG loader)
        # ... other shim files as needed
    ]) + gen_sources,
    include_directories: inc,
    dependencies: [dep_wayland_client, dep_wayland_egl, dep_egl,
                   dep_glesv2, dep_png /* , dep_glu if needed */],
    link_args: ['-L/usr/lib/gl4es', '-lGL',
                '-Wl,-rpath,/usr/lib/gl4es'],
    sources_<hack>_harness_c_args: common_c_args,
    sources_xscreensaver_compat_c_args: common_c_args,
    c_args: vendored_c_args,
)
```

The `<hack>_harness.c` is a copy of `glmatrix_harness.c` with one line
changed (the external symbol it references):

```c
extern struct xscreensaver_function_table glmatrix_xscreensaver_function_table;
```
→
```c
extern struct xscreensaver_function_table <name>_xscreensaver_function_table;
```

(In a future round, the harness should iterate a table of effects and
load the right one at startup via `-e <name>`. For round 7 we just
prove one binary works.)

### 4e. Test on real hardware

```bash
cd build
LIBGL_NOTEST=1 LIBGL_ES=2 LIBGL_NOBANNER=1 ./<hack>_demo
```

Expected success:
- No GL errors on stderr
- The hack's animation actually plays (visual confirmation on the
  Wayland overlay)
- Quits cleanly on any key press

If GL4ES errors appear:
- `LIBGL_NOTEST` not set → re-set it
- `GL_INVALID_ENUM` on `glBegin` → GL4ES not actually in the link path;
  verify `ldd <hack>_demo | grep libGL` shows `/usr/lib/gl4es/libGL.so.1`
- Driver rendering artifacts (issue #405 reference) → file a bug; may
  be unavoidable, consider custom shim

### 4f. Document in CHANGELOG.md

Each new port gets an entry:
- Source URL + license confirmation
- Edits made to hack source (typically just `#include` lines)
- Shim symbols added (if any)
- Verified-on-hardware date + signal

## §6 — Known limitations (round 7 baseline)

| Limitation | Impact | Plan |
|---|---|---|
| GLU quadrics (gluNewQuadric / gluSphere / gluCylinder / gluDisk) not implemented | Hacks that draw 3D primitives via GLU (e.g. `boing.c`) won't render | Vendor ptitSeb/GLU (autotools, ~3K LoC, MIT) as a separate static lib, link into gl*_demo executables |
| `gluBuild2DMipmaps` not implemented | A few texture-loading hacks (`boxed.c`) need it | Add as part of the GLU vendoring |
| `gluPerspective` / `gluLookAt` (only 2 GLU calls glmatrix uses) | We don't implement them yet, glmatrix won't render | Add a ~15-line shim; trivial math |
| X11 color allocation (`XAllocColor`, `XParseColor`) | Hacks that build a color palette need it | Add to shim when next port needs it |
| Text rendering (`XDrawString`, `XftDrawString*`) | Hacks that overlay text via Xlib | Out of scope for round 7; defer |
| Display lists (`glNewList`, `glCallList`) | Hacks using list optimization won't compile-link in worst case; GL4ES supports them in master | Verify per-port; GL4ES has reasonable coverage |
| `JPointer` / `jrand`-style helpers from utils/ | Many hacks use `frand`, `random()` | Already covered (`frand`, `random`) |
| `mi->cycles` not checked → hacks with N-cycles exit never exit | E.g. `bsod`, `cwaves` run forever | Add a `MI_CYCLES` check in the harness |

These are **deliberately deferred** to keep round 7 minimal. Each is a
self-contained addition to the shim (or a vendored library), not a
fundamental rework of the pipeline.

## §7 — Rollback / alternative strategies (if GL4ES fails on real hardware)

If the coordinator runs `gl4es_triangle` on the Debian forky arm64 box
and **it doesn't render correctly**, the failure modes are:

### 7a. `EGL_BAD_DISPLAY` during GL4ES init
- **Symptom**: `LIBGL: Error while gathering supported extension
  (eglInitialize: EGL_BAD_DISPLAY)`, then all `gl*` calls fail.
- **Fix**: verify `LIBGL_NOTEST=1` is set. If still failing, file a
  GL4ES issue and use 7b.

### 7b. GL4ES fundamentally broken on this Mesa/panfrost combo
- **Symptom**: even `glClear` fails, or rendering is completely wrong
  after a few frames.
- **Fallback 1 (smaller custom shim)**: write a ~15K LoC C shim that
  implements ONLY the ~96 GL1 functions xscreensaver hacks actually
  use (immediate mode, matrix stack, lighting, textures, display
  lists). Emit GLSL ES 3.0 shaders via fixed code paths; no
  shader-permutation FPE generator. Estimated effort: 3-6 engineer-months.
- **Fallback 2 (LLVMpipe + XWayland)**: give up native and run the
  hack under XWayland with software rasterization. Defeats the entire
  project's purpose; only do this as a last resort to keep the
  shipping demo working while a real fix lands.

### 7c. Specific hacks have rendering artifacts
- **Symptom**: a specific hack draws black/wrong/missing pixels where
  GL4ES's fixed-function emulation doesn't quite match desktop GL.
- **Workaround**: hand-port THAT hack to use GLES2 shaders directly
  (like `wl-screenhack.c`'s `triangle_init`). Documented in
  CHANGELOG.md as a "GL4ES-incompatible hack".

The architecture is designed so any of 7a/7b/7c is recoverable without
touching the rest of the pipeline.
